# Alembic Database Migrations Guide

## Overview

Alembic is our database migration tool - think of it as version control (like Git) for your database schema. It allows us to track, apply, and rollback database changes in a controlled, reproducible way.

## Why We Use Alembic

- **Version Control**: Track every schema change with migration files
- **Team Collaboration**: Everyone runs the same migrations to stay in sync
- **Rollback Capability**: Undo changes if something goes wrong
- **Production Safety**: Test migrations in dev before deploying to production
- **Automated Deployment**: CI/CD can automatically apply migrations

## Common Commands

### Check Migration Status

```bash
# See current migration version
alembic current

# See full migration history
alembic history --verbose
```

### Apply Migrations

```bash
# Apply all pending migrations (most common)
alembic upgrade head

# Apply one migration forward
alembic upgrade +1

# Apply to specific version
alembic upgrade <revision_id>
```

### Rollback Migrations

```bash
# Rollback one migration
alembic downgrade -1

# Rollback to specific version
alembic downgrade <revision_id>

# Rollback all migrations
alembic downgrade base
```

## Creating New Migrations

### When to Create a Migration

Create a migration whenever you modify database schema:
- Adding/removing tables
- Adding/removing columns
- Changing column types
- Adding/removing indexes
- Modifying constraints

### Step-by-Step: Adding a New Field

**Example:** Adding a `duration` field to the `Call` model

**Step 1:** Modify your SQLAlchemy model

Edit `backend/models/models.py`:

```python
class Call(Base):
    __tablename__ = "calls"

    id = Column(Integer, primary_key=True, index=True)
    caller_number = Column(String, nullable=False)
    receiver_number = Column(String, nullable=False)
    duration = Column(Integer, nullable=True)  # NEW FIELD
    # ... other fields
```

**Step 2:** Generate migration

```bash
alembic revision --autogenerate -m "add duration to calls table"
```

This creates a new file in `alembic/versions/` like:
- `abc123def456_add_duration_to_calls_table.py`

**Step 3:** Review the migration

Open the generated file and verify the changes:

```python
def upgrade() -> None:
    op.add_column('calls', sa.Column('duration', sa.Integer(), nullable=True))

def downgrade() -> None:
    op.drop_column('calls', 'duration')
```

**Step 4:** Test the migration

```bash
# Apply it
alembic upgrade head

# Verify it works
alembic current

# Test rollback (optional)
alembic downgrade -1
alembic upgrade head
```

**Step 5:** Commit to Git

```bash
git add backend/models/models.py
git add alembic/versions/abc123def456_add_duration_to_calls_table.py
git commit -m "Add duration field to Call model"
git push
```

**Step 6:** Team members pull and apply

When teammates pull your code:

```bash
git pull
alembic upgrade head  # Automatically adds the duration column
```

## Migration File Anatomy

Every migration has two key functions:

### `upgrade()`
Contains operations to **apply** the change (move forward)

```python
def upgrade() -> None:
    op.add_column('calls', sa.Column('recording_url', sa.String(500)))
    op.create_index('idx_calls_status', 'calls', ['status'])
```

### `downgrade()`
Contains operations to **undo** the change (rollback)

```python
def downgrade() -> None:
    op.drop_index('idx_calls_status', 'calls')
    op.drop_column('calls', 'recording_url')
```

## Common Migration Operations

### Add Column
```python
op.add_column('table_name', sa.Column('column_name', sa.String(255), nullable=True))
```

### Remove Column
```python
op.drop_column('table_name', 'column_name')
```

### Create Table
```python
op.create_table(
    'new_table',
    sa.Column('id', sa.Integer(), primary_key=True),
    sa.Column('name', sa.String(100), nullable=False)
)
```

### Drop Table
```python
op.drop_table('table_name')
```

### Add Index
```python
op.create_index('idx_name', 'table_name', ['column_name'])
```

### Remove Index
```python
op.drop_index('idx_name', 'table_name')
```

### Modify Column Type
```python
op.alter_column('table_name', 'column_name',
    existing_type=sa.String(100),
    type_=sa.String(200))
```

## Best Practices

### 1. Always Review Autogenerated Migrations

Alembic's autogenerate is smart but not perfect. Always review generated migrations:

```bash
# After generating
alembic revision --autogenerate -m "description"

# Open the file in alembic/versions/ and review
```

Common issues autogenerate might miss:
- Data migrations (moving/transforming existing data)
- Complex constraints
- Renaming columns (sees as drop + add)

### 2. Never Edit Applied Migrations

Once a migration is committed and others have run it, **never modify it**. Instead:

```bash
# Create a new migration to fix the issue
alembic revision --autogenerate -m "fix previous migration issue"
```

### 3. One Logical Change Per Migration

Keep migrations focused:

✅ Good:
- `add_user_email_column.py`
- `create_sessions_table.py`
- `add_index_to_calls_status.py`

❌ Bad:
- `random_database_changes.py` (does 10 unrelated things)

### 4. Test Before Committing

Always test your migration on a dev database:

```bash
# Apply
alembic upgrade head

# Verify database state
psql -U postgres -d urdu_voice_ai
\d table_name  # Check table structure

# Test rollback
alembic downgrade -1

# Re-apply
alembic upgrade head
```

### 5. Descriptive Migration Messages

```bash
# Good
alembic revision --autogenerate -m "add cascade delete to transcript foreign key"

# Bad
alembic revision --autogenerate -m "fix"
```

## Troubleshooting

### "No such revision" Error

**Cause:** Your database version doesn't match migration files

**Solution:**
```bash
# Check current version
alembic current

# Check available migrations
alembic history

# Stamp to specific version (use with caution!)
alembic stamp head
```

### "Target database is not up to date"

**Cause:** Migrations pending

**Solution:**
```bash
alembic upgrade head
```

### Autogenerate Detects Nothing

**Cause:** Models not imported in `alembic/env.py`

**Solution:** Verify `alembic/env.py` imports your models:
```python
from backend.models.models import Base
target_metadata = Base.metadata
```

### Authentication Failed

**Cause:** Wrong credentials in `.env`

**Solution:** Check your `.env` file:
```bash
DB_USER=postgres
DB_PASSWORD=your_actual_password
DB_HOST=localhost
DB_PORT=5432
DB_NAME=urdu_voice_ai
```

## Environment Variables

We use environment variables for database credentials (never commit passwords!).

### Local Development

Your `.env` file (not committed to Git):
```bash
DB_USER=postgres
DB_PASSWORD=your_local_password
DB_HOST=localhost
DB_PORT=5432
DB_NAME=urdu_voice_ai
```

### Production

Set environment variables on your production server (AWS, Heroku, etc.):
```bash
export DB_USER=prod_user
export DB_PASSWORD=secure_prod_password
export DB_HOST=prod-db.example.com
export DB_PORT=5432
export DB_NAME=urdu_voice_ai
```

## CI/CD Integration

### Example GitHub Actions Workflow

```yaml
name: Run Migrations

on:
  push:
    branches: [main]

jobs:
  migrate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Set up Python
        uses: actions/setup-python@v2
        with:
          python-version: '3.10'
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Run migrations
        env:
          DB_USER: ${{ secrets.DB_USER }}
          DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
          DB_HOST: ${{ secrets.DB_HOST }}
          DB_NAME: ${{ secrets.DB_NAME }}
        run: alembic upgrade head
```

## Advanced: Manual Migrations

Sometimes autogenerate isn't enough (data migrations, complex logic).

### Create Empty Migration

```bash
alembic revision -m "migrate user roles to new format"
```

### Example: Data Migration

```python
def upgrade() -> None:
    # Get connection
    connection = op.get_bind()

    # Run custom SQL or Python logic
    connection.execute(
        text("UPDATE calls SET status = 'completed' WHERE status = 'done'")
    )

def downgrade() -> None:
    connection = op.get_bind()
    connection.execute(
        text("UPDATE calls SET status = 'done' WHERE status = 'completed'")
    )
```
